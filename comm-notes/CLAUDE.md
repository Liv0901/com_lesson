# CLAUDE.md：通訊原理講義站

這份文件寫給協助開發本專案的 AI（Claude Code、Codex 等）。動手新增或修改任何檔案前，請先讀完本文件，並以本文件的規則為準。

本專案有兩份規則文件，分工如下：

- **`AGENTS.md`**：知識庫（`raw/`、`wiki/`）的規則，參考 Karpathy 的 LLM Wiki 做法。處理資料匯入、提問、健檢時以它為準。
- **`CLAUDE.md`（本文件）**：講義網站（`index.html`、`lessons/`、`assets/`）的規則。做網頁時以本文件為準。

講義的**內容**來自 `wiki/`，講義的**格式**依本文件。

## 1. 專案目的

- 這是一個「通訊原理」課程的講義網站，給通訊電子工程系大學部學生課前預習、課後複習使用。
- 每一回講義介紹一個主題（例如：訊號與頻譜、AM 調變、FM 調變、取樣定理），讓學生在 15 到 20 分鐘內讀完並能做課後練習。
- 目標是建立一套固定格式，之後每新增一回講義，只要複製樣板、填入內容、更新目錄即可。

## 2. 讀者與寫作風格

- 讀者：大二、大三學生，已學過微積分與基本電路，但對通訊系統是第一次接觸。
- 一律使用**繁體中文**（臺灣用語），專有名詞第一次出現時附英文，例如「調變指數（modulation index）」。
- 先講直覺、再給公式、最後用數字算一次。不要一開始就丟出推導。
- 句子短、主動語態。避免「眾所周知」「顯然」這類讓初學者挫折的字眼。
- 單位使用 SI 制，數字與單位之間空一格：`1 kHz`、`10 ms`。

## 3. 技術限制

- 純靜態網站：只用 HTML + CSS，**不使用**任何框架、建置工具或 npm 套件。
- 部署在 GitHub Pages，必須能直接從 `index.html` 開啟瀏覽。
- 全站只有一個樣式表 `assets/style.css`。不要在 HTML 裡寫 `<style>` 或 `style="..."`。
- 不使用 JavaScript。互動需求（例如展開詳解）用原生 `<details>` / `<summary>`。
- 公式用 HTML 的 `<var>`、`<sub>`、`<sup>` 撰寫，不載入 MathJax 等外部函式庫。
- 圖片一律用內嵌 SVG 畫，顏色只能用 `style.css` 定義好的 class（見第 7 節），這樣深色模式才會正確。

## 4. 目錄結構

```
/
├── index.html              首頁：網站介紹 + 講義目錄
├── CLAUDE.md               本文件（AI 開發規則）
├── AGENTS.md               知識庫規則（LLM Wiki）
├── README.md               給人看的專案說明
├── assets/
│   └── style.css           全站唯一樣式表
├── raw/                    原始資料（唯讀，見 AGENTS.md）
├── wiki/                   AI 維護的知識庫（見 AGENTS.md）
├── templates/
│   └── lesson-template.html  新講義的樣板，只能複製、不要直接上線
└── lessons/
    ├── 01-signals-and-spectrum.html
    ├── 02-am-modulation.html
    └── 03-fm-modulation.html
```

新增講義後，請同步更新上面這張目錄樹。

## 5. 檔案命名規則

- 講義檔放在 `lessons/`，檔名格式：`兩位數編號-英文主題.html`
  - 例：`03-fm-modulation.html`、`04-sampling-theorem.html`
  - 英文全小寫，單字之間用連字號 `-`，不要用空格、底線或中文。
- 編號代表上課順序，從 `01` 開始連續編號，不可跳號或重複。
- 新圖片若真的需要外部檔案（盡量不要），放在 `assets/img/`，檔名格式同上，例如 `03-fm-spectrum.svg`。

## 6. 講義頁的固定結構

每一回講義**必須**依照下列順序包含這些區塊（樣板已經排好）：

| 順序 | 區塊 | HTML / class | 內容要求 |
|---|---|---|---|
| 1 | 頁首 | `.site-header` | 與其他頁完全相同，不要改 |
| 2 | 標題區 | `.lesson-head` | 麵包屑、`第 N 回`、標題、預估閱讀時間 |
| 3 | 學習目標 | `.goals` | 3 條，以「能夠……」開頭，可被檢驗 |
| 4 | 核心觀念 | `<h2>` + 段落 | 2 到 4 個小節，先講直覺 |
| 5 | 公式 | `.formula` | 每個公式下方用 `.where` 說明每個符號與單位 |
| 6 | 圖解 | `<figure class="figure">` | 至少 1 張內嵌 SVG，要有 `figcaption` |
| 7 | 範例題 | `.example` | 至少 1 題，詳解放在 `<details>` 裡 |
| 8 | 常見誤解 | `.pitfall` | 1 到 2 個學生最常犯的錯 |
| 9 | 重點整理 | `.summary` | 3 到 5 條，每條一句話 |
| 10 | 課後練習 | `.practice` | 3 題，由易到難 |
| 11 | 上下頁 | `.pager` | 連到上一回與下一回；沒有就連回首頁 |

## 7. 可用的樣式元件

只使用下列 class。若真的需要新元件，先加到 `assets/style.css` 並在本節補上說明，再使用。

- 版面：`.wrap`（內容寬度）、`.site-header`、`.site-footer`
- 首頁：`.hero`、`.hero-trace`、`.lesson-list`（每回一個 `<li>`，尚未完成的加 `class="soon"`）
- 講義：`.lesson-head`、`.crumbs`、`.lesson-no`、`.meta`、`.goals`、`.formula`（內含 `.eq`、`.where`）、`.figure`、`.example`、`.pitfall`、`.summary`、`.practice`、`.pager`
- SVG 內：`.trace`（紅色訊號線）、`.env`（藍色虛線，包絡或輔助線）、`.axis`（座標軸）、`.bar`（頻譜柱）、`<text>` 會自動套用灰色文字
- 顏色變數（只寫在 CSS 裡）：`--paper`、`--ink`、`--muted`、`--signal`、`--link`、`--panel`

視覺風格：方格紙背景、深藍墨色文字、紅色訊號線。全站只有首頁那條波形有自動動畫，講義頁不要加任何動畫。

## 8. 新增一回講義的流程

0. 先讀 `wiki/index.md` 與該主題的概念頁（含 `related` 列出的頁面），講義內容以知識庫為準；知識庫資料不足時，先請老師補 `raw/` 資料並匯入，不要自行編造。
1. 複製 `templates/lesson-template.html` 到 `lessons/`，依第 5 節命名。
2. 把樣板裡所有 `【】` 佔位文字換成實際內容，確認沒有殘留的 `【`。
3. 修改 `<title>`：`第 N 回：主題｜通訊原理講義站`。
4. 設定 `.pager`：本回的「上一回」連到前一個檔案；**同時回去修改前一回**的「下一回」連到本回。
5. 更新 `index.html` 的 `.lesson-list`：
   - 若目錄中已有這一回（`class="soon"`），移除 `soon`，把標題改成連結並補上一句簡介。
   - 若沒有，新增一個 `<li>`，放在正確的編號位置。
6. 更新第 4 節目錄樹與 `README.md` 的「目前講義」清單。
7. 依 `AGENTS.md` 第 8 節，在概念頁 frontmatter 填上 `lesson:`，並在 `wiki/log.md` 追加 `publish` 紀錄。
8. 依第 10 節檢查。

## 9. 修改既有內容的規則

- 只改被要求修改的部分，不要順手重寫其他段落或改動排版。
- 不要更動已發布講義的檔名（會讓學生收藏的連結失效）。
- 修正公式或數值時，同一頁的範例題、重點整理也要一起檢查是否需要跟著改。
- 改動 `style.css` 時，要確認所有講義頁在淺色與深色模式下都還正常。

- [ ] 首頁目錄、上下頁連結、目錄樹、README 都已更新
- [ ] 手機寬度（約 375px）下沒有橫向捲動
