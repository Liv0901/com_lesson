# AGENTS.md：通訊原理知識庫（LLM Wiki）

這份文件寫給協助本專案的 AI 代理（Codex、Claude Code、OpenCode 等）。
本專案參考 Andrej Karpathy 的 LLM Wiki 做法：**由 AI 逐步建立並維護一個持續累積的 Markdown 知識庫**，再從知識庫產生給學生看的講義網頁。

開始任何工作前，請先讀完本文件，再讀 `wiki/index.md` 和 `wiki/log.md` 最後 5 筆紀錄，了解知識庫目前的狀態。

---

## 1. 核心想法

- 一般的 RAG 每次提問都要重新翻原始文件，知識不會累積。
- 本專案的做法是：每加入一份新資料，AI 就讀過、整理、**寫進知識庫**，更新相關頁面、補上交叉連結、標出矛盾。
- 知識只整理一次，之後持續更新。知識庫會隨每一份資料、每一次提問變得更完整。
- 分工：
  - **老師（使用者）**：挑選資料、決定重點、提出問題、審核內容。
  - **AI**：摘要、分類、建立連結、更新索引與紀錄等所有整理工作。

## 2. 三層架構

| 層 | 資料夾 | 誰寫 | 說明 |
|---|---|---|---|
| 原始資料 | `raw/` | 老師放入 | 課本摘錄、上課筆記、考古題、文章。**AI 只能讀，絕對不能修改或刪除。** |
| 知識庫 | `wiki/` | AI 全權維護 | 由原始資料整理出的概念頁、資料摘要頁、問答頁、總覽。 |
| 規則 | `AGENTS.md`、`CLAUDE.md` | 老師與 AI 共同修訂 | 本文件管知識庫；`CLAUDE.md` 管講義網站。 |

講義網站（`index.html`、`lessons/`）是知識庫的「出版品」：新講義的內容一律先從 `wiki/` 取材，格式則依 `CLAUDE.md`。

## 3. 目錄結構

```
/
├── AGENTS.md                本文件：知識庫規則（中文）
├── CLAUDE.md                講義網站規則
├── raw/                     原始資料（唯讀）
│   ├── README.md            放資料的說明
│   └── YYYY-MM-DD-主題.md    每份原始資料一個檔案
├── wiki/                    知識庫（AI 維護）
│   ├── index.md             內容目錄：所有頁面 + 一句話摘要
│   ├── log.md               時間紀錄：每次匯入、提問、檢查
│   ├── overview.md          課程總覽與整體脈絡
│   ├── concepts/            概念頁：一個觀念一頁
│   ├── sources/             資料摘要頁：raw/ 每份資料對應一頁
│   └── answers/             問答頁：值得保留的提問結果
├── lessons/                 講義網頁（依 CLAUDE.md）
└── templates/               講義樣板
```

## 4. 檔案命名

- 一律使用**英文小寫 + 連字號**，例如 `concepts/carsons-rule.md`。中文名稱寫在頁面標題與 frontmatter 的 `title`。
- `raw/` 與 `wiki/sources/` 的檔名開頭加日期：`2026-11-16-course-outline.md`，兩邊檔名相同，方便對照。
- 一個概念只能有一頁。新增前先查 `wiki/index.md`，已有就更新，不要重複建立。

## 5. 頁面格式

每個 `wiki/` 頁面開頭都要有 YAML frontmatter：

```yaml
---
title: FM 調變
type: concept          # concept | source | answer | overview
sources: [2026-11-16-course-outline]   # 這頁內容來自哪些 raw 資料
related: [am-modulation, modulation-index, carsons-rule]
updated: 2026-11-16
lesson: 03-fm-modulation   # 若已做成講義，填講義檔名；沒有就省略
---
```

正文規則：

- 使用**繁體中文**（臺灣用語），專有名詞第一次出現附英文。
- 概念頁固定段落：`## 一句話定義`、`## 直覺說明`、`## 公式`、`## 常見誤解`、`## 相關概念`、`## 出處`。
- 公式用一般文字或行內程式碼寫，例如 `β = Δf / fm`，並說明每個符號與單位。
- 連結一律用相對路徑的 Markdown 連結，例如 `[卡森法則](carsons-rule.md)`，GitHub 和 Obsidian 都能點。
- 每一個重要說法都要能追到 `## 出處`，指向 `../sources/` 的摘要頁。
- 不同資料說法衝突時，**不要自行刪掉任一方**，在頁面加上 `> ⚠️ 矛盾：……` 區塊，寫明兩邊出處，等老師決定。

## 6. 三種操作

### 6.1 匯入（Ingest）

老師說「匯入 raw/某檔案」時：

1. 完整讀過該份原始資料。
2. 用 3 到 5 點向老師回報重點，確認要強調什麼（老師說「直接做」則跳過）。
3. 在 `wiki/sources/` 建立同名摘要頁：資料是什麼、重點、涉及哪些概念。
4. 更新或新增相關的 `wiki/concepts/` 頁面，補上交叉連結（一份資料常會動到 5 到 15 頁）。
5. 若影響整體脈絡，更新 `wiki/overview.md`。
6. 更新 `wiki/index.md`。
7. 在 `wiki/log.md` 最後**追加**一筆紀錄。

### 6.2 提問（Query）

老師對知識庫提問時：

1. 先讀 `wiki/index.md` 找出相關頁面，再讀這些頁面。
2. 回答時註明引用了哪些頁面。
3. 若答案有保留價值（比較表、整理、新發現的關聯），存成 `wiki/answers/` 的新頁面，並更新 `index.md` 與 `log.md`。

### 6.3 健檢（Lint）

老師說「健檢知識庫」時，檢查並回報：

- 頁面之間的矛盾、被新資料推翻的舊說法
- 沒有任何頁面連進來的孤兒頁
- 被提到很多次、卻還沒有自己頁面的概念
- `index.md` 漏列或已失效的頁面
- 缺漏的出處、frontmatter 欄位
- 建議接下來該補的資料或該問的問題

修正後在 `log.md` 追加一筆 `lint` 紀錄。

## 7. 索引與紀錄

**`wiki/index.md`（依內容分類）**：每頁一行，格式：

```
- [FM 調變](concepts/fm-modulation.md)：訊息改變載波頻率，振幅不變。
```

依「總覽 / 概念 / 資料摘要 / 問答」分區。每次匯入都要更新。

**`wiki/log.md`（依時間）**：只能在最後追加，不可修改舊紀錄。每筆用固定開頭：

```
## [2026-11-16] ingest | 通訊原理課程大綱
- 新增：sources/2026-11-16-course-outline.md、concepts/fm-modulation.md
- 更新：index.md、overview.md
```

類型只有 `ingest`、`query`、`lint`、`publish`（產生講義）四種。用 `grep "^## \[" wiki/log.md | tail -5` 即可看到最近 5 筆。

## 8. 從知識庫產生講義（Publish）

老師說「把某概念做成第 N 回講義」時：

1. 讀該概念頁與 `related` 列出的頁面，作為講義內容來源。
2. 依 `CLAUDE.md` 第 8 節流程建立 `lessons/` 網頁（格式、樣式、檢查清單都以 `CLAUDE.md` 為準）。
3. 回到概念頁，在 frontmatter 填上 `lesson:` 欄位。
4. 在 `log.md` 追加一筆 `publish` 紀錄。

## 9. 禁止事項

- 不可修改、搬移、刪除 `raw/` 內任何檔案。
- 不可修改 `log.md` 的舊紀錄。
- 不可編造原始資料沒有的數據或出處；知識庫不足時，直接說「目前知識庫沒有這項資料」，並建議要補什麼。
- 不可一次大規模改寫頁面風格；只改這次任務相關的部分。

## 10. 完成前檢查清單

- [ ] `raw/` 沒有被改動
- [ ] 新增或修改的頁面都有完整 frontmatter
- [ ] 所有 Markdown 連結都能開啟（相對路徑正確）
- [ ] `wiki/index.md` 已列出所有頁面
- [ ] `wiki/log.md` 已追加本次紀錄
- [ ] 若有產生講義，已通過 `CLAUDE.md` 第 10 節檢查
